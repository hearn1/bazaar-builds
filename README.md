# bazaar-builds

Curator toolchain for [The Bazaar](https://www.playthebazaar.com/) build catalogs used by [bazaar_tracker](https://github.com/hearn1/bazaar_tracker).

## What the enricher does

`bazaar_build_enricher.py` fetches category and post pages from bazaar-builds.net, extracts item mentions and win records, and emits a normalized JSON artifact for human review. It is intentionally read-only with respect to `*_builds.json` — the curator inspects the artifact and hand-edits the catalog in the tracker repo. The `compare` subcommand diffs a fresh artifact against an existing hero catalog and produces a markdown proposal showing missing items and new archetype candidates.

## How to run it

Install dependencies once:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Fetch evidence for a hero (defaults assume a sibling `bazaar_tracker` checkout at `../bazaar_tracker`):

```bash
python bazaar_build_enricher.py https://bazaar-builds.net/category/builds/karnok-builds/ \
    --hero Karnok --days 30 --output artifacts/karnok_bazaar_builds_summary.json
```

If your tracker checkout is in a non-sibling location, pass explicit paths:

```bash
python bazaar_build_enricher.py https://bazaar-builds.net/category/builds/dooley-builds/ \
    --hero Dooley --days 30 \
    --catalog-dir /path/to/bazaar_tracker \
    --names-file /path/to/bazaar_tracker/card_cache_names.txt \
    --output artifacts/dooley_bazaar_builds_summary.json
```

Diff the artifact against the hero catalog and emit a review proposal:

```bash
python bazaar_build_enricher.py compare \
    artifacts/karnok_bazaar_builds_summary.json \
    ../bazaar_tracker/karnok_builds.json \
    --output artifacts/karnok_build_update_proposal.md
```

`--names-file` must point at the live `card_cache_names.txt` in your tracker checkout (generated by `tracker.py refresh-images`). Do not vendor a copy here — it goes stale immediately.

## Automated pipeline status

The automated builds refresh pipeline is documented in [`docs/pipeline-operations.md`](docs/pipeline-operations.md). It is currently held at `local_dry_run` with `dry_run: true`; `shadow_cron` and `live_cron` require the manual phase gates in that runbook and are not enabled by default.

## Schema contract

`*_builds.json` files are owned by the tracker repo. The JSON Schema is at [`builds_schema.json`](https://github.com/hearn1/bazaar_tracker/blob/main/builds_schema.json) in the tracker repo — the consumer defines the contract. CI in this repo validates any `*_builds.json` produced by the enricher against that schema before review.
